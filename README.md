# Вариант 27. Почтовый клиент

Консольное приложение на C# (.NET 8), демонстрирующее применение паттернов
проектирования **Template Method** и **Memento** на примере почтового клиента.

Приложение создаёт письма разных типов (деловое, рассылка, приглашение) с общим
порядком подготовки, а также позволяет сохранять незаконченный черновик и
восстанавливать его со всеми изменениями (тема, тело, подпись, вложения).

---

## Задача

Нужно реализовать консольное приложение почтового клиента, в котором:

1. **Письма разных типов** (деловое, рассылка, приглашение) имеют общую
   структуру подготовки — *шапка → тело → подпись → вложения → отправка* — но
   отличаются реализацией отдельных шагов. Общий алгоритм не должен
   дублироваться в каждом типе письма, а новый тип должен добавляться без
   правки существующих классов.
2. **Черновик письма** можно отложить (сохранить) и позже восстановить со
   всеми изменениями, не раскрывая его внутреннее состояние наружу.

Эти два требования определяют выбор паттернов: **Template Method** — для
типов писем, **Memento** — для черновиков.

---

## Использованные паттерны

### Template Method

**Проблема.** Деловое письмо, рассылка и приглашение готовятся по одному и тому
же сценарию, но каждый шаг у них отличается. Если реализовывать каждый тип
отдельным классом «с нуля», общий алгоритм (порядок шагов и вызов отправки)
продублируется трижды. Любое изменение порядка шагов придётся вносить во все
классы, и легко получить рассинхронизацию.

**Решение.** Абстрактный класс `EmailTemplate` содержит каркасный метод
`PrepareAndSend`, который жёстко фиксирует порядок шагов:

```
PrepareHeader → PrepareBody → PrepareSignature → AddAttachments → Send
```

`PrepareHeader` и `PrepareBody` — абстрактные, их обязаны реализовать наследники.
`PrepareSignature` и `AddAttachments` — виртуальные, с поведением по умолчанию.
`Send` — приватный: наследник не может его переопределить или обойти.
Конкретные шаблоны `BusinessEmailTemplate`, `NewsletterEmailTemplate`,
`InvitationEmailTemplate` переопределяют только отличающиеся шаги.

**Что даёт:**
- общий алгоритм хранится в одном месте;
- новый тип письма = новый подкласс, существующий код не меняется
  (принцип открыт-закрыт);
- порядок шагов нельзя случайно нарушить в наследнике.

### Memento

**Проблема.** Нужно сохранить черновик и восстановить его позже целиком —
включая тему, тело, подпись и список вложений. Если хранить снимок в `Program`
или во внешнем классе через публичные поля, это ломает инкапсуляцию
`EmailDraft`. Если копировать поля вручную снаружи — при добавлении нового поля
копирование придётся править во всех местах и легко забыть одно из них.

**Решение.**
- `EmailDraft` — **originator**: сам создаёт снимок (`Save()`) и сам
  восстанавливается из него (`Restore()`), поэтому знает о своих полях только
  он сам.
- `EmailMemento` — **снимок**: хранит тему, тело, подпись и **копию** списка
  вложений. Поля `internal`, снаружи их прочитать нельзя.
- `DraftCaretaker` — **опекун**: держит `Stack<EmailMemento>`, умеет сохранить
  текущее состояние и восстановить последний снимок, но не знает, что внутри
  снимка. Стек даёт многошаговый откат.

**Что даёт:**
- инкапсуляция черновика сохранена — `Caretaker` не касается его полей;
- новое поле в черновике добавляется в `EmailDraft` и `EmailMemento` в одном
  месте, внешний код не меняется;
- вложения копируются (`ToArray()`), поэтому изменения черновика после снимка
  не «протекают» в снимок.

более ранний. Видно, что восстанавливаются все поля, включая вложения.

## Запуск

Требуется [.NET SDK 8.0](https://dotnet.microsoft.com/download) или новее.

```bash
git clone <URL-репозитория>
cd MailClient
dotnet run
```

Или через IDE: открыть `MailClient.csproj` в Visual Studio / Rider и нажать
`F5`.
